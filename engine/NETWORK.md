# Engine network access

This inventory covers fixed destinations in Notchbee and the bundled engine. The app talks to its embedded engine over authenticated loopback. Notchbee uses only its bundled engine and sends no product telemetry, analytics, or crash reports.

| Feature | Destinations |
| --- | --- |
| OpenAI and Codex | `auth.openai.com` for OAuth, discovery and keys, `chatgpt.com` for subscription inference and quota, and `api.openai.com` for API-key or managed inference, model discovery and optional cloud speech. |
| Anthropic and Claude | `api.anthropic.com` for inference and account/quota APIs, `claude.ai`, `claude.com`, and `platform.claude.com` for account/OAuth flows, and `mcp-proxy.anthropic.com` for Claude-hosted MCP when enabled in Claude. |
| Cursor | `api.cursor.com`, `api2.cursor.sh`, and `cursor.com` for API, login and model and account operations. The SDK fetches Cursor feature-gate configuration from Cursor's API. The SDK is installed unmodified and may send usage events to Cursor under Cursor's privacy policy. `origin.cursor.com` serves Cursor Origin Git repositories. |
| xAI and Grok | `auth.x.ai`, `accounts.x.ai`, `cli-chat-proxy.grok.com`, and `api.x.ai` for OAuth, quota, API requests and optional cloud speech. |
| Google Antigravity | `accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com`, `cloudcode-pa.googleapis.com`, and `daily-cloudcode-pa.googleapis.com` for login, account and quota calls. `dl.google.com` serves provider releases. |
| Other providers | `opencode.ai` for OpenCode subscription limits, `api.meta.ai` for Muse maintenance, `openrouter.ai` for optional cloud speech and its model list, and the endpoints selected by the configured provider, ACP agent or API base URL for inference and authentication. |
| Claude and Cursor SDK setup | `registry.npmjs.org` serves pinned tarballs after the user approves the named SDK and version in Settings. The engine verifies SHA-512 hashes before extraction. |
| Catalogs, prices and installers | `raw.githubusercontent.com` for the upstream model manifest and LiteLLM prices, `api.github.com` as a pricing fallback and for releases, `github.com` for releases, `registry.npmjs.org` for version lookups and packages, `downloads.claude.ai` and `downloads.cursor.com` for provider binaries, and `cdn.agentclientprotocol.com` for the ACP agent registry. GitHub downloads may redirect to release asset hosts such as `release-assets.githubusercontent.com`. Provider update checks use public registry and release endpoints while enabled. |
| Source control | `github.com`, `api.github.com`, `gitlab.com`, `bitbucket.org`, `api.bitbucket.org`, `dev.azure.com`, `codeberg.org`, `gitea.com`, `git.cafe`, `staging.git.cafe`, `origin.cursor.com` and configured Git or enterprise hosts. Git follows the configured remotes. Source-control operations can send repository identifiers, credentials, diffs or commit content to the configured forge. |
| Optional engine integrations | `api.expo.dev` and Expo-provided session or asset hosts for EAS device operations. The SSH and Simlock device adapters use configured hosts. The native app ships its own speech pipeline. Its engine disables the upstream on-device speech and browser installers. `github.githubassets.com` and `www.google.com` appear in shared upstream favicon helpers. The native chat renders no remote images or favicons. `app.t3.codes` and `nightly.app.t3.codes` are upstream link destinations. Fresh embedded installations have no hosted T3 Connect relay configuration. |
| Native speech and updates | `huggingface.co` and its HTTPS redirect/CDN hosts serve the verified FluidInference model files. macOS manages model downloads for the local Apple Speech fallback through `AssetInventory`. Sparkle uses the configured HTTPS appcast and the download and release-note URLs it advertises. The feed is `https://github.com/HILAYTRIVEDI/notchbee/releases/latest/download/appcast.xml`. Sparkle system profiling and the embedded engine’s Bun crash uploads are disabled in the app. |
| Explicit actions and extensions | Configured Git remotes, SSH and linked environments, MCP and 1Password integrations, custom provider endpoints, package repositories chosen by installers, and links opened in the default browser. Displayed setup commands and links include `cursor.com`, `cli.kiro.dev`, `fx.sh`, `dev.meta.ai` and `x.ai`. Independently installed agents, MCP tools, terminals, scripts and package managers can initiate their own requests. |

Agent dictation sends the reviewed transcript, app name, window title and selected or nearby field text to the destination thread. Clean dictation sends the transcript to the model configured for cleanup or text generation. Both native transcription paths process microphone audio on-device. Cloud audio transcription is a separate authenticated engine API for configured `api.openai.com`, `openrouter.ai` or `api.x.ai` providers. Automatic first titles in the bundled engine use the thread’s model. Explicit text-generation actions use the model configured for that feature. The bundled engine does not silently retry text generation on a different provider.

The Usage page reads local provider history for token totals, cost estimates, model and provider breakdowns, and session counts. The page also reads the latest quota windows and reset times when supported by a configured provider. Pricing is downloaded as public reference data. The engine keeps a private local operational log. Copy diagnostics includes app and macOS versions and engine connection status. Terminals use live process information for terminal status and output. Chat and workflow state are stored locally for history, resumption and replay.
