# Engine build

Build on Apple Silicon with Bun 1.4.1. `scripts/build-engine.sh` installs dependencies from the frozen engine lockfile and runs `bun build --compile --target=bun-darwin-arm64`. The result is `build/engine/notchbee-engine`. The build prints its size in bytes and writes the distribution notices to `build/engine/THIRD_PARTY_NOTICES`. Include the notices with the app distribution. The executable can be copied and run independently of the checkout, Bun on PATH, or a sibling `node_modules` directory.

- Bun implements the pinned server's `node:sqlite` API, including WAL and workers. The build uses the server's existing migrations. The engine writes operational messages to standard output and standard error for the app's local log.
- `node-pty` needs both a native addon and its executable `spawn-helper`. FFF workspace search and `ffi-rs` have native loaders that also expect files at real paths. The build embeds their Darwin arm64 packages as a compressed asset. The launcher extracts them to a private temporary directory and removes it on process exit. A force-killed process can leave that directory for macOS temporary-file cleanup.
- Bun's compiled package-JSON resolution is enabled so the extracted packages can resolve their dependencies. Automatic dotenv and bunfig loading is disabled. The small Effect dependency patch replaces a wildcard re-export of Bun's built-in `ws` with named exports so the compiled server can start.
- Upstream web assets, browser launch and preview, native audio transcription, installation, background-service and update commands, Tailscale exposure, and hosted relay are disabled. The import omits upstream product analytics and exporters. The HTTP and WebSocket API still carries the upstream protocol and text post-processing. Provider executables such as Codex and Claude Code are installed independently and found through PATH or provider settings.
- The Claude and Cursor SDKs are downloaded separately at runtime. Their development declarations resolve from the frozen lockfile. The build rejects SDK code in the engine executable or staged archive.
- The packaged helper requires signing for Hardened Runtime and loads staged native packages and consented provider SDKs from disk.

The supported runtime dependency is macOS. The executable embeds Bun and has no separate JavaScript fallback. To relink it with a rebuilt Bun, set `NOTCHBEE_BUN_RUNTIME=/absolute/path/to/bun` when running `scripts/build-engine.sh`. The build tool on PATH stays at 1.4.1. The replacement executable should be a compatible macOS arm64 runtime. See the [corresponding source and LGPL notice](../THIRD_PARTY_NOTICES.md).
